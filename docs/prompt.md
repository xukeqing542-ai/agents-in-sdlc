# Prompt 与 Skill 对比方案

作者：徐苛清｜个人设计稿，尚未请求大模型。当前 `llm_stage.py dry-run` 仅对预设模拟回复作解析和回退测试。

## Skill 接口

- `validate_schema(rows)`：校验付款编号、订单号、发票号、金额、供应商字段；失败即停止。
- `index_invoices(rows)`：按去除边缘空格后的发票号索引重复记录。
- `detect_exceptions(rows)`：输出规则异常标签，不对付款作审批。
- `retrieve_policy(query)`：返回演示制度编号及原文，证据不足时返回无依据。
- `human_review_gate(findings)`：固定待人工复核状态，禁止自动批准。

这些步骤是原型中的确定性工具流程；模型还未实际编排调用工具。

## 待比较的提示词

V1：你是付款复核助手。根据已识别的异常和检索到的制度，用一句话解释风险，提供条款编号。所有付款需人工审核。

V2：你是辅助财务人员准备待核问题的助手。只能使用输入的付款字段和检索到的演示条款；不能补写不存在的制度、判断违规或批准付款。严格输出 JSON 的 `reason`、`citation`、`action` 三个键：`citation` 必须原样复制所给来源编号，`action` 只能是“人工复核”；当来源缺失、输入冲突或证据不足时，返回无法判断并指出待补字段。说明只是风险提示，不是最终结论。

## 评测方案与当前状态

在同一组冻结的案例上对两版提示词各调用模型一次，并保存请求、原始回复、解析结果、所引条款、耗时及人工评分。主要指标：①有效 JSON 比例；②引用编号正确率；③无依据拒答率；④越权审批次数；⑤人工评定解释可用率。目标是降低错误引用和越权输出，同时不牺牲可用性。

当前仅有离线解析回退测试：合法引用可解析，来源错误或声称自动批准时回退。尚无真实模型 V1/V2 对照数据，因此不能声称 V2 优于 V1。
