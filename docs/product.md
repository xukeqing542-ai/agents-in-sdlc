# 费用付款复核 Agent｜产品需求与迭代记录

作者：徐苛清｜2026-09-25｜个人项目，所有业务材料均为演示数据。

## 场景、用户与成功标准

用户是负责费用付款核验的财务人员。工作任务是发现缺订单、缺发票、重复发票、超出演示金额阈值及无效金额，并把记录交给有权限的人审核。输入为结构化付款 CSV；输出是待复核清单、异常类型、演示制度引用及处理状态。不作实际付款决定或违规认定。

验收目标：①字段错误时停止并说明原因；②每条异常可追溯到原始付款编号及规则；③找不到可用制度时说明“无依据”；④审批状态始终为待人工复核；⑤项目数据与演示制度不可被误认为真实企业材料。

## 功能与交互流程

1. 用户选择 CSV，确认表头含 `payment_id, order_id, invoice_id, amount, vendor`。
2. 页面先显示输入记录数、待复核数和“必须人工确认”状态。
3. 查看六步工具轨迹及最多 30 条异常清单；中文描述异常及“核对原始单据”的待办。
4. 在“查询演示制度”输入问题，查看条款编号或无依据回退。
5. 缺表头时页面提示“输入未通过校验”，不展示虚假的统计数字。

- 已检查：本地 HTTP 请求验证首页、样本运行（240 条／76 项预设待核）、缺字段输入、条款检索四条路径；离线模型回复解析的有效引用与违规回复回退检查通过。该检查属于作者自测，不能称为外部用户试用。
- 未实现：企业数据与制度接入、模型 API 真实调用、真实财务人员试用、线上部署、自动付款审批。

## 评测与限制

原始 240 条为按相同规则生成的合成记录，不代表真实业务准确率。另有 20 条手工编写的合成挑战案例，与生成器分开存储，在项目规则已知的条件下得到 20/20 逐例异常标签一致；该结果不是盲测。案例包括临界金额、负数、无效金额、空发票、重复发票、空格、组合异常等。查看 `data/holdout_20.csv`、`data/holdout_20_expected.json` 和 `data/holdout_20_result.json`。
